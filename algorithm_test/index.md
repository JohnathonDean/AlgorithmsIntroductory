# 算法学习总览

## 算法的作用

### 算法可以解决什么问题

算法的本质，是把一个问题拆解成一组明确、可执行、可验证的步骤。只要问题能够被清楚描述，并且输入、输出和约束条件明确，通常就可以设计出对应算法。

算法常见解决的问题包括：

- 查找问题：在大量数据中快速找到目标元素或目标区间。
- 排序问题：把无序数据整理成有序结构，为后续操作提供基础。
- 遍历问题：按一定规则访问数组、树、图中的元素或节点。
- 判定问题：判断某个条件是否成立，例如图中是否有环、二叉搜索树是否合法。
- 优化问题：在多个可行方案中找到最优解，例如最短路径、最小代价、最大收益。
- 计数问题：统计路径数量、方案数、连通分量数量等。

学习算法时，真正需要培养的是识别问题模型的能力。面对一个题目，应该逐步判断：

- 数据结构是什么，是数组、树还是图？
- 题目要求的是查找、遍历、计数还是最优化？
- 是否存在有序性、单调性、递归结构、局部最优性质？
- 是否可以通过空间换时间，或通过预处理降低总成本？

## 设计算法

### 分治法的思想

分治法是最重要的算法设计思想之一。它的核心流程是：

1. 分解：把原问题拆成若干个规模更小但形式相同的子问题。
2. 解决：递归地解决这些子问题。
3. 合并：把子问题的结果组合成原问题的结果。

分治法适合这类问题：

- 原问题与子问题结构相同。
- 子问题之间相对独立。
- 子问题的解能够被有效合并。

典型例子包括：

- 归并排序：拆成左右两部分，分别排序，再合并。
- 快速排序：根据基准元素分区后，递归处理左右区间。
- 二分查找：每次排除一半不可能的区域，本质上也是缩小规模求解。

学习分治法时，不要只记住“这是递归”，而要抓住关键能力：

- 能不能准确拆分子问题。
- 能不能写清楚递归终止条件。
- 能不能说明子问题的结果如何合并。

### 伪代码的写法规则

伪代码用于表达算法的核心逻辑，它不依赖某一门具体编程语言，但必须具备清晰、规范、可还原的特点。写伪代码的目标，不是追求形式好看，而是让算法思路足够准确，便于交流、推导和落地实现。

#### 伪代码的编写设计思路

编写伪代码之前，应该先明确算法本身的结构，而不是一上来就写步骤。一个比较稳妥的思路是：

1. 先确定输入和输出。
2. 再明确算法的核心过程是什么，例如查找、遍历、递归、分治或状态转移。
3. 然后拆出关键步骤，判断哪些是主流程，哪些是边界处理。
4. 最后再用统一的伪代码格式表达出来。

设计伪代码时，建议重点想清楚这些问题：

- 这个算法是顺序执行、分支执行，还是递归执行？
- 核心变量有哪些，它们分别表示什么？
- 循环和终止条件是什么？
- 返回结果是什么，在哪一步产生？
- 边界输入出现时，算法是否仍然成立？

也就是说，伪代码的设计本质上是在做“流程建模”。如果算法流程本身没有想清楚，伪代码通常也会写得混乱。

#### 伪代码的编写规则和语法

伪代码虽然不要求完全遵循某门语言的语法，但仍然要有基本规则，这样才能保证阅读和实现的一致性。

常见编写规则包括：

- 开头写清输入 `Input` 和输出 `Output`。
- 使用统一且含义明确的变量名。
- 分支结构写清楚条件，例如 `if...else`。
- 循环结构写清楚起点、终点和更新方式，例如 `for`、`while`。
- 递归过程写清楚递归入口、递归终止条件和返回值。
- 关键步骤按顺序编号或按缩进分层，避免逻辑混乱。

常见的伪代码表达习惯可以参考下面这种形式：

```text
Algorithm BinarySearch(nums, target)
Input: 有序数组 nums，目标值 target
Output: 目标值下标；若不存在则返回 -1

left <- 0
right <- length(nums) - 1

while left <= right
    mid <- left + (right - left) / 2
    if nums[mid] == target
        return mid
    else if nums[mid] < target
        left <- mid + 1
    else
        right <- mid - 1

return -1
```

从语法层面看，伪代码通常只要求做到：

- 赋值统一，例如使用 `<-` 或 `=`，全文保持一致。
- 缩进清楚，体现层级关系。
- 关键字统一，例如 `if`、`else`、`while`、`for`、`return`。
- 不混用多种风格，避免一部分像 `Python`，一部分像 `C++`。

#### 伪代码的编写习惯要求

除了规则和语法，良好的编写习惯也很重要。很多伪代码看不懂，不是因为算法难，而是因为表达混乱。

建议养成以下习惯：

- 先写主流程，再补边界处理，不要一开始就陷入细节。
- 一个变量只表达一种含义，避免反复更换用途。
- 对关键步骤使用简短注释，说明该步骤的目的。
- 尽量用短句和标准结构，不写模糊描述。
- 复杂算法先分模块，再分别写伪代码。
- 对返回值、异常情况和特殊情况单独说明。

判断一段伪代码写得是否合格，可以用三个标准：

- 别人能不能顺着它复现出代码。
- 自己隔一段时间后还能不能快速看懂。
- 能不能据此检查边界、循环和返回值是否正确。

例如写二分查找的伪代码时，真正要养成的习惯不是死记模板，而是主动检查：

- 区间是左闭右闭还是左闭右开。
- `mid` 的计算方式是否安全。
- 找到目标后是否应该继续收缩边界。
- 循环结束后返回值是否仍然合法。

## 分析算法

### 算法的分析思路

分析算法时，建议按照下面的顺序进行：

1. 明确输入规模和数据结构。
2. 找出算法中最主要的操作。
3. 判断这些操作会执行多少次。
4. 分析是否使用了递归、辅助数组、栈、队列、哈希表等额外空间。
5. 最后总结时间复杂度、空间复杂度和边界行为。

分析时不要只看代码长短，而要抓住“主导成本”：

- 排序中，核心成本通常来自比较和交换。
- 二分查找中，核心是每次能排除多少搜索空间。
- 树遍历中，核心是每个节点是否只被访问一次。
- 图算法中，核心通常是节点数 `V` 和边数 `E`。
- 动态规划中，核心通常是状态数量与每个状态的转移成本。

除了复杂度分析，还应同步考虑：

- 正确性：算法为什么一定正确。
- 边界情况：空输入、重复值、单节点、极端数据时是否仍然成立。
- 实现风险：是否容易越界、死循环、递归过深。

### 算法的时间复杂度和空间复杂度

时间复杂度描述的是：随着输入规模增大，算法执行步骤数量如何增长。

空间复杂度描述的是：算法在运行过程中额外需要多少辅助存储空间。

很多初学者知道 `O(n)`、`O(n log n)` 这些记号，但真正困难的是“不知道怎么分析出来”。因此这部分不仅要记住复杂度名称，更要掌握分析方法。

#### 如何分析时间复杂度

分析时间复杂度时，可以按下面步骤进行：

1. 先确定输入规模，通常记作 `n`。
2. 找出算法中最核心、执行次数最多的操作。
3. 统计这类操作会随着 `n` 增长执行多少次。
4. 忽略常数项、低阶项，只保留增长最快的部分。

分析时应注意一个原则：时间复杂度衡量的是“增长趋势”，不是精确运行时间。因此：

- `3n + 5` 记作 `O(n)`
- `2n^2 + 10n + 7` 记作 `O(n^2)`
- `n log n + n` 记作 `O(n log n)`

可以按常见代码结构来判断：

- 单层循环遍历 `n` 次，通常是 `O(n)`。
- 双重循环，各循环都接近 `n` 次，通常是 `O(n^2)`。
- 每次把问题规模缩小一半，通常是 `O(log n)`。
- 一边遍历，一边在每次遍历中做 `log n` 级操作，通常是 `O(n log n)`。

例如：

```text
for i from 0 to n - 1
    do constant work
```

上面每轮只做常数次操作，共执行 `n` 轮，所以时间复杂度是 `O(n)`。

再例如：

```text
for i from 0 to n - 1
    for j from 0 to n - 1
        do constant work
```

外层循环 `n` 次，内层每次也执行 `n` 次，因此总操作次数约为 `n * n`，时间复杂度是 `O(n^2)`。

如果是二分查找这种写法：

```text
while left <= right
    mid <- ...
    根据比较结果丢掉一半区间
```

由于每一轮都能把问题规模减半，所以循环次数约为 `log n`，时间复杂度是 `O(log n)`。

#### 如何分析递归算法的时间复杂度

递归算法的时间复杂度通常要看两个因素：

- 子问题被拆成几个。
- 每个子问题的规模缩小了多少。

例如归并排序可以理解为：

- 把问题拆成两个规模约为 `n/2` 的子问题。
- 合并两个有序数组时还需要线性时间 `O(n)`。

因此它的总复杂度是 `O(n log n)`。

再例如二叉树遍历：

- 每个节点只访问一次。
- 总节点数为 `n`。

所以无论是前序、中序还是后序遍历，时间复杂度通常都是 `O(n)`。

分析递归时，最实用的判断方法是：

- 如果每个元素或节点只被处理有限次，往往是 `O(n)`。
- 如果每层递归都处理全部数据，且层数有 `log n` 层，往往是 `O(n log n)`。

#### 如何分析空间复杂度

空间复杂度分析的是算法在运行时“额外占用了多少空间”，这里要特别注意，通常不把输入数据本身算进去，而只统计新增的辅助空间。

分析空间复杂度时，可以按下面顺序判断：

1. 是否申请了额外数组、矩阵、哈希表、队列、栈等结构。
2. 这些结构的大小是否会随着 `n` 增长。
3. 是否使用递归，如果使用，递归调用栈有多深。

常见判断方法如下：

- 只用了几个固定变量，如 `left`、`right`、`mid`，通常是 `O(1)`。
- 额外开了一个长度为 `n` 的数组，通常是 `O(n)`。
- 递归深度为 `log n`，递归栈空间通常是 `O(log n)`。
- 递归深度最坏达到 `n`，递归栈空间通常是 `O(n)`。

例如：

- 冒泡排序、选择排序、插入排序通常只在原数组上操作，只需要少量临时变量，因此空间复杂度通常是 `O(1)`。
- 归并排序需要额外数组来合并结果，因此空间复杂度通常是 `O(n)`。
- 二分查找若使用迭代写法，通常只需几个变量，因此空间复杂度是 `O(1)`。
- 树的递归遍历虽然没有显式开大数组，但递归调用栈会占空间，因此空间复杂度与树高相关。

#### 分析复杂度时的常见误区

学习复杂度时，常见错误主要有下面几类：

- 只数循环层数，不看每层循环实际执行次数。
- 忽略递归调用栈带来的空间开销。
- 把输入本身占用的空间也算进辅助空间。
- 只记平均情况，不看最坏情况。
- 看到两段顺序执行的循环，就错误地写成 `O(n^2)`，实际上如果是 `O(n) + O(n)`，应记作 `O(n)`。

例如下面这种结构：

```text
for i from 0 to n - 1
    do constant work

for j from 0 to n - 1
    do constant work
```

这不是 `O(n^2)`，而是 `O(n) + O(n)`，最终记作 `O(n)`。

#### 常见复杂度可以这样理解

- `O(1)`：操作次数基本固定，不随数据规模明显增长。
- `O(log n)`：每次都能把问题规模显著缩小，例如二分查找。
- `O(n)`：完整扫描一次数据，或每个元素只处理一次。
- `O(n log n)`：常见于高效排序和一些分治算法。
- `O(n^2)`：常见于双重循环比较，小规模可接受，大规模压力明显。

#### 学习复杂度时要注意

- 最好、平均、最坏复杂度可能不同。
- 时间和空间经常需要权衡。
- 复杂度只是重要标准之一，不是唯一标准。

例如：

- 归并排序性能稳定，时间复杂度是 `O(n log n)`，但需要额外空间。
- 快速排序平均性能优秀，但最坏情况下可能退化到 `O(n^2)`。
- 堆排序同样是 `O(n log n)`，但实现理解成本通常高于前两者。

## 主要算法概览

### 排序

排序算法研究的是如何把一组无序数据调整为有序数据。它既是基础专题，也是很多复杂问题的前置步骤。

主要的排序算法：

- 冒泡排序
- 选择排序
- 插入排序
- 归并排序
- 快速排序
- 堆排序

可以把这些算法大致分成两类：

- 基础排序：冒泡、选择、插入，适合理解比较、交换和数组操作。
- 高效排序：归并、快速、堆排序，适合理解分治、分区和堆结构。

学习排序时，建议重点比较以下维度：

- 时间复杂度
- 空间复杂度
- 稳定性
- 是否原地排序
- 适用场景

### 二分查找和二叉树

#### 二分查找算法

二分查找建立在“有序”或“单调”前提之上。每次通过中间位置与目标比较，都能排除一半不可能的区间，因此时间复杂度通常是 `O(log n)`。

- 标准二分查找
- 左边界查找
- 右边界查找

这一部分的重点不只是会背模板，而是要真正理解：

- 区间定义是什么。
- 循环结束条件是什么。
- 找到目标后是立即返回，还是继续收缩边界。
- 最终结果如何验证。

二分查找特别能训练边界控制能力，很多错误都集中在：

- `left` 和 `right` 的初始值写错。
- 更新边界时少加一或少减一。
- 重复元素情况下不清楚该返回哪个位置。

#### 二叉树

二叉树是学习递归、遍历和层次结构问题的核心载体。很多抽象的算法思想，在树结构中会变得非常直观。

- 前序遍历
- 中序遍历
- 后序遍历
- 层序遍历
- 最大深度
- 二叉搜索树查找
- 二叉搜索树合法性判断

二叉树学习的重点有两条主线：

- 深度优先：通过递归处理当前节点与左右子树的关系。
- 广度优先：通过队列一层一层地处理节点。

其中二叉搜索树 `BST` 很重要，因为它利用“左子树值更小、右子树值更大”的性质，让查找过程具备类似二分的效率优势。

### 动态规划算法

动态规划用于解决具有“重叠子问题”和“最优子结构”的问题。它的核心不是记结论，而是先定义状态，再写出状态转移。

一个典型的动态规划设计过程通常包括：

1. 定义状态。
2. 写出状态转移方程。
3. 确定初始条件。
4. 选择计算顺序。
5. 视情况进行空间优化。

常见问题包括：

- 斐波那契数列
- 爬楼梯
- 0-1 背包
- 最长上升子序列
- 编辑距离

动态规划的难点通常不在代码，而在建模：

- 状态定义不清楚。
- 转移关系想不出来。
- 初始条件漏掉。
- 顺序写错导致用到了未计算的状态。

当前仓库暂未展开这一专题，但它是后续非常值得补齐的重点内容。

### 贪心算法

贪心算法的思想是：每一步都选择当前看起来最优的方案，希望最终得到全局最优解。

它的优点是：

- 逻辑通常更直接。
- 实现往往更简洁。
- 在合适问题上效率很高。

但贪心算法不能只凭“直觉感觉合理”来使用，必须能说明为什么局部最优选择是安全的，为什么不会破坏整体最优解。

典型贪心问题包括：

- 活动选择
- 区间调度
- 某些硬币找零问题
- Huffman 编码
- 某些图算法中的局部选择过程

学习贪心时，建议重点训练这类判断：

- 当前策略有没有反例？
- 这题真的适合贪心，还是其实应该用动态规划？
- 局部最优如何推导出全局最优？

### 图算法

图算法处理的是“节点之间存在连接关系”的问题，是算法学习中综合性很强的一部分。

#### 基本的图算法

基础图算法主要包括：

- `BFS`
- `DFS`
- 无权图最短路径
- 拓扑排序
- 并查集

这些算法主要解决的问题包括：

- 遍历图中的所有节点。
- 判断节点之间是否连通。
- 求无权图中的最短路径。
- 处理依赖关系和任务顺序。
- 动态维护集合归属关系。

#### 最小生成树

最小生成树问题关注的是：在带权无向连通图中，用总代价最小的方式把所有节点连接起来。

常见算法有：

- Kruskal 算法
- Prim 算法

这部分内容通常会同时训练：

- 贪心思想
- 边权排序
- 并查集或优先队列的使用

#### 单源最短路径

单源最短路径问题研究的是：从一个起点出发，到图中其他所有节点的最短距离。

常见算法包括：

- Dijkstra
- Bellman-Ford
- 无权图上的 `BFS`

学习这部分时，需要重点区分：

- 图是否带权。
- 是否存在负权边。
- 目标是求某一个点的最短路，还是所有点的最短路。

## 总结

算法学习不应只是背题型，而应逐步建立一套稳定的问题分析能力：

- 识别问题模型
- 选择合适的数据结构
- 设计正确的解法
- 分析复杂度
- 验证边界条件

从当前仓库的内容来看，已经形成了一条比较清晰的基础主线：

- 排序：训练数组操作、比较和分治思想。
- 二分查找：训练有序性利用与边界控制。
- 二叉树：训练递归、遍历和结构化思维。
- 图算法：训练建模、搜索、连通性与路径分析。

如果后续继续扩展，比较自然的方向是：

- 动态规划
- 贪心算法
- 最小生成树
- 单源最短路径
- 链表、哈希表、栈与队列等基础数据结构专题

只要始终围绕“原理、实现、复杂度、边界、测试”这几个维度推进，算法学习就会从零散知识点逐步沉淀为完整体系。
