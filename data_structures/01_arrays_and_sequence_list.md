# 线性表：数组描述


## 概述

C++常用的数据描述方法是数组描述和链式描述，线性表可以用来说明这两种方法。


## 线性表的数据结构

### 1. 线性表的概念定义

线性表 `linearList` 也叫做有序表 `orderedList` 是由零个或多个元素组成的有序有限序列。

- 除第一个元素外，每个元素都有唯一前驱
- 除最后一个元素外，每个元素都有唯一后继
- 空表也是线性表

线性表表示元素之间的一对一次序关系。

### 2. 线性表包含的基本操作

线性表上定义的基本操作包括：

- 创建一个线性表
- 撤销一个线性表
- 判断线性表是否为空
- 求线性表的长度
- 查找第 `k` 个元素
- 查找元素 `x`
- 删除第 `k` 个元素
- 将元素 `x` 插入为第 `k` 个元素
- 顺序输出线性表的元素

### 3. 线性表的抽象数据类型说明

线性表先作为抽象数据类型讨论。

抽象数据类型给出：

- 数据对象
- 数据对象上的操作

抽象数据类型不规定具体存储结构，也不规定操作的具体实现算法。

对 `linearList` 的抽象数据类型说明，通常可写成如下接口形式：

- `empty()`：若线性表为空，返回 `true`，否则返回 `false`
- `size()`：返回线性表中的元素个数
- `get(index)`：返回索引为 `index` 的元素
- `indexOf(theElement)`：返回元素 `theElement` 第一次出现的位置。若不存在则返回-1
- `erase(index)`：删除索引为 `index` 的元素，索引大于 `index` 的元素其索引减1
- `insert(index, theElement)`：在索引为 `index` 的位置插入元素 `theElement`，索引大于 `index` 的元素其索引加1
- `output()`：从左到右输出线性表中的元素

### 4. 线性表抽象类

在线性表的 C++ 描述中，抽象数据类型可以用抽象类表示。抽象类给出 `linearList` 的接口说明，具体操作由派生类实现。线性表抽象类通常包含下列纯虚函数：

```cpp
template<class T>
class linearList
{
  public:
    virtual ~linearList() {};
    virtual bool empty() const = 0;
    virtual int size() const = 0;
    virtual T& get(int theIndex) const = 0;
    virtual int indexOf(const T& theElement) const = 0;
    virtual void erase(int theIndex) = 0;
    virtual void insert(int theIndex, const T& theElement) = 0;
    virtual void output(std::ostream& out) const = 0;
};

```

这一部分的重点是先把“线性表应该支持哪些操作”固定下来。后面无论使用数组描述还是链式描述，本质上都是在实现这组接口。

## 数组描述

## 1. 数组描述

数组描述也叫顺序描述，它的核心思想是：用一段地址连续的存储空间来保存线性表中的元素。

对于一维数组，只要知道数组首地址和元素下标，就能够通过地址公式直接定位到目标元素。因此，数组描述最大的特点是支持按位置快速访问元素。

数组描述的主要特点可以概括为：

- 逻辑上相邻的元素，物理上也连续存放
- 可以通过下标直接访问第 `i` 个元素
- 插入和删除时，往往需要移动多个元素
- 容量通常需要预先确定，或通过扩容机制动态调整

从学习角度看，数组描述的优势和局限都很典型：

- 优势在于随机访问快
- 局限在于中间插入和删除代价高

这也正是后面链式描述要解决的问题。


## 2. `arrayList` 类

书中用 `arrayList` 来实现 `linearList`。这类顺序表通常维护三个核心数据成员：

| 名称 | 含义 |
| --- | --- |
| `element` | 指向底层数组 |
| `arrayLength` | 数组容量 |
| `listSize` | 当前线性表长度 |

这三个量中，最关键的是区分：

- `listSize`：已经存放的元素个数
- `arrayLength`：最多可存放的元素个数

任何插入、删除、扩容或越界判断，都会同时依赖这两个量。

`arrayList` 的典型职责包括：

- 用构造函数建立一个空的顺序表
- 用析构函数释放动态申请的数组空间
- 检查下标是否合法
- 提供查找、插入、删除等基本操作

在实际实现中，几个基本操作的理解尤其重要：

- `get(index)`：通过下标直接访问数组元素，因此效率较高
- `indexOf(theElement)`：通常需要从前到后顺序扫描
- `erase(index)`：删除后需要将后续元素整体前移
- `insert(index, theElement)`：插入前需要为新元素腾出位置，因此后续元素整体后移

这说明顺序表虽然访问方便，但修改中间位置的数据通常要付出“元素搬移”的代价。

如果把复杂度直观地理解：

- 按位置访问通常较快
- 在尾部附近插入删除相对简单
- 在表头或表中间插入删除代价更高

因此，`arrayList` 更适合“查询较多、插入删除较少”的使用场景。

## 3. 迭代器

顺序表实现通常首先要解决对象建立和资源管理问题。

在此基础上，如果希望顺序表像标准库容器一样方便遍历，就需要提供迭代器。

对于数组描述的线性表，迭代器的实现相对自然，因为底层本身就是连续存储空间。可以把迭代器理解成“指向数组元素位置的访问工具”。

引入迭代器之后，有几个直接好处：

- 可以统一元素访问方式
- 可以支持从头到尾的顺序遍历
- 更容易和 C++ 标准库中的算法风格对应起来

对这一章而言，迭代器不必一开始就深入实现细节，更重要的是理解它的角色：

- 它不是新的存储结构
- 它是对“访问顺序表元素方式”的进一步封装

如果底层数组发生扩容，原先基于旧地址的迭代器通常会失效，这一点和后面学习 `vector` 时的行为是一致的。


## 4. `vector` 的描述

标准库中的 `vector` 可以看作一种更加成熟的动态顺序表实现。

它和这里讨论的 `arrayList` 有很多共同点：

- 都使用连续存储空间保存元素
- 都支持按下标随机访问
- 都存在容量和当前长度的区别
- 都可能在容量不足时进行扩容

从这个角度看，学习 `arrayList` 的意义并不只是会写一个顺序表类，更重要的是理解 `vector` 背后的基本原理。

可以把两者的联系概括为：

- `arrayList` 更偏向教材中的数据结构实现
- `vector` 更偏向工程实践中的标准容器

理解了顺序表之后，再看 `vector` 的常见行为就会更自然：

- 为什么 `operator[]` 可以直接访问元素
- 为什么中间插入删除可能导致大量元素移动
- 为什么容量不足时会触发重新分配空间
- 为什么扩容后原有指针或迭代器可能失效

因此，这一章其实也是理解 STL 顺序容器的基础。


## 总结

这一章的核心任务，是从抽象数据类型 `linearList` 出发，理解线性表怎样用数组进行描述。

可以把主要认识归纳为：

- 线性表先定义“有哪些操作”，再讨论“如何实现这些操作”
- 数组描述的关键优势是连续存储和随机访问
- 顺序表的主要代价在于插入删除时的元素搬移
- `arrayList` 是教材中顺序表的典型实现
- `vector` 可以看作顺序表思想在标准库中的成熟应用

后面学习链式描述时，可以始终拿这一章作对照：数组描述访问快但修改成本高，而链式描述则在插入删除方面更灵活。
