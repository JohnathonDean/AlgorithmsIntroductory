# 线性表：链表


## 概述

C++ 中线性表既可以用数组描述，也可以用链式描述。上一章讨论的是顺序存储，这一章讨论的是同一个 `linearList` 抽象数据类型的链式实现。

链表这一章的重点，不是再定义一个新的线性表，而是说明：

- 线性表的逻辑结构可以保持不变
- 底层存储方式可以从连续空间改成链接结构
- 存储方式一旦变化，基本操作的实现方法和代价也会随之变化

因此，这一章可以看作是上一章“数组描述”的直接对照。


## 线性表的数据结构

### 1. 线性表的概念定义

线性表 `linearList` 是由零个或多个元素组成的有序有限序列。

- 除第一个元素外，每个元素都有唯一前驱
- 除最后一个元素外，每个元素都有唯一后继
- 空表也是线性表

线性表关注的是元素之间的先后次序关系，而不是元素值本身的大小关系。

这一点在链表中尤其重要，因为链表中的“前后次序”不是靠数组下标体现，而是靠节点之间的链接关系体现。

### 2. 线性表包含的基本操作

线性表的基本操作在链式描述中并没有改变，仍然包括：

- 创建一个线性表
- 撤销一个线性表
- 判断线性表是否为空
- 求线性表的长度
- 查找第 `k` 个元素
- 查找元素 `x`
- 删除第 `k` 个元素
- 将元素 `x` 插入为第 `k` 个元素
- 顺序输出线性表的元素

这说明链表和数组描述的区别，不在于“支持的操作不同”，而在于“这些操作如何实现”。

### 3. 线性表的抽象数据类型说明

线性表仍然先作为抽象数据类型讨论。

抽象数据类型给出：

- 数据对象
- 数据对象上的操作

抽象数据类型不规定具体存储结构，也不规定算法实现细节。

因此，对 `linearList` 的接口说明，在链式描述中依然可以写成：

- `empty()`：若线性表为空，返回 `true`，否则返回 `false`
- `size()`：返回线性表中的元素个数
- `get(index)`：返回索引为 `index` 的元素
- `indexOf(theElement)`：返回元素 `theElement` 第一次出现的位置。若不存在则返回 `-1`
- `erase(index)`：删除索引为 `index` 的元素
- `insert(index, theElement)`：在索引为 `index` 的位置插入元素 `theElement`
- `output()`：从左到右输出线性表中的元素

这一部分和上一章的作用相同，都是先固定逻辑接口，再讨论底层实现。

### 4. 线性表抽象类

在线性表的 C++ 描述中，抽象数据类型仍然可以用抽象类表示。链表并不是重新定义一套接口，而是继续实现同一个 `linearList` 抽象类。

```cpp
template<class T>
class linearList
{
  public:
    virtual ~linearList() {};
    virtual bool empty() const = 0;
    virtual int size() const = 0;
    virtual T& get(int theIndex) const = 0;
    virtual int indexOf(const T& theElement) const = 0;
    virtual void erase(int theIndex) = 0;
    virtual void insert(int theIndex, const T& theElement) = 0;
    virtual void output(std::ostream& out) const = 0;
};

```

这说明链表章节的真正任务是：在不改变接口的前提下，用另一种物理表示完成相同的线性表操作。

## 链式描述

## 1. 链式描述

链式描述的核心思想是：元素不再要求存放在一段连续空间中，而是把每个元素放入一个节点中，再通过链接关系把这些节点串起来。

与顺序表不同，链表中的逻辑顺序不是由数组下标决定，而是由节点之间的指针关系决定。

链式描述的主要特点可以概括为：

- 节点在内存中的位置可以分散
- 逻辑相邻的元素依靠链接关系连接
- 按位置访问时通常需要从头逐个查找
- 插入和删除时通常不需要整体搬移元素

从学习角度看，链式描述的优势和局限同样很明显：

- 优势在于局部插入和删除更灵活
- 局限在于不能像数组那样直接随机访问

参考书用一句非常关键的话概括了这一点：链式表示使用的是任意布局，而不是连续布局。也正因为如此，链表和数组在访问方式上有了本质区别。


## 2. `chain` 类

书中通常先定义节点，再定义链表类。对于最基本的单链表，可以把主要组成理解为：

- `chainNode`：表示单个节点
- `chain`：表示整个链表

一个最基本的单链表节点通常包含两部分：

- 数据域 `element`
- 指向后继节点的指针 `next`

而链表类 `chain` 通常至少维护以下状态：

| 名称 | 含义 |
| --- | --- |
| `firstNode` | 指向第一个节点 |
| `listSize` | 当前链表长度 |

这和上一章的 `arrayList` 非常类似。顺序表靠 `element + arrayLength + listSize` 描述一个线性表，单链表则靠 `firstNode + listSize` 描述一条链。

`chain` 的典型职责包括：

- 建立一个空链表
- 释放整条链表占用的节点空间
- 检查下标是否合法
- 提供查找、插入、删除等基本操作

在实际实现中，几个基本操作的理解尤其重要：

- `get(index)`：不能直接按下标定位，必须从 `firstNode` 开始逐节点向后移动
- `indexOf(theElement)`：需要从头到尾顺序比较
- `erase(index)`：关键不在删除节点本身，而在修改前驱节点的链接
- `insert(index, theElement)`：关键不在写入数据，而在把新节点正确接入原链

这说明链表虽然避免了顺序表那种大规模元素搬移，但很多操作要先“找到位置”，因此访问代价并不会自动降低。

如果把复杂度直观地理解：

- 按位置访问通常较慢
- 按值查找通常也需要顺序扫描
- 一旦找到前驱节点，插入删除会更直接
- 链表更适合修改较多、随机访问要求不高的场景

单链表实现里最重要的意识有两个：

- 前驱节点往往决定插入删除能否顺利完成
- 指针修改顺序必须正确，否则整条链可能断开

另外，链表对象通常涉及动态内存管理，因此析构函数、拷贝构造和赋值操作都不能忽略。复制链表时，通常需要逐节点复制，而不能简单复制入口指针。


## 3. 头结点、循环链表和双向链表

在最基本的单链表之上，参考书还会继续讨论几种常见变体，它们的目的都是让某些操作更方便，或者让链表适应不同场景。

### 头结点

头结点本身通常不存放实际业务数据，它的主要作用是简化边界处理。

有了头结点之后：

- 空表和非空表的处理方式更统一
- 在表头插入与在中间插入更接近
- 在表头删除与在中间删除更接近

因此，头结点的真正价值不在于“多了一个节点”，而在于：

- 把原本很多特殊情况改写成普通情况

### 循环链表

循环链表的核心特点是：

- 最后一个节点不再指向空，而是重新连回链中的某个位置，最常见的是连回第一个节点

这样带来的变化包括：

- 某些循环处理更自然
- 从表尾回到表头不需要重新定位入口
- 遍历的终止条件不能再简单写成“遇到空指针停止”

因此，循环链表虽然表达能力更强，但也更容易因为终止条件写错而产生死循环。

### 双向链表

双向链表在每个节点中增加前驱链接，因此节点通常包含：

- 前驱指针
- 数据域
- 后继指针

它带来的主要好处是：

- 可以双向遍历
- 某些插入删除操作不再像单链表那样强依赖前驱节点查找

但代价同样明确：

- 每个节点需要更多空间
- 每次插入删除都要维护更多链接关系

因此，双向链表体现了一个很典型的结构设计思想：

- 功能更灵活，往往意味着实现更复杂、空间开销更大


## 4. 迭代器的描述

上一章顺序表在连续空间基础上引入了迭代器，链表同样也可以提供迭代器来完成从左到右的遍历。

不过，链表迭代器和顺序表迭代器的直觉并不完全一样：

- 顺序表迭代器本质上更接近数组位置
- 链表迭代器本质上更接近“当前节点的引用或指针”

对链表来说，引入迭代器之后有几个直接好处：

- 可以统一访问链表元素的方式
- 可以把“逐节点向后移动”的过程封装起来
- 更容易与标准库算法式的遍历风格对应

但链表迭代器也有自己的限制：

- 它不支持像数组那样按下标跳转
- 它的移动通常依赖当前节点的后继链接

从这个角度看，链表迭代器再次体现了链式描述的本质：

- 它强调顺序访问
- 不强调随机访问

因此，这一章不仅是在学习链表本身，也是在学习“访问方式会随着底层结构改变”这一更深一层的思想。


## 总结

这一章的核心任务，是从抽象数据类型 `linearList` 出发，理解线性表怎样用链式结构进行描述。

可以把主要认识归纳为：

- 线性表的逻辑定义不变，改变的是物理存储方式
- 链式描述的关键特征是节点分散存放、依靠链接维持次序
- 单链表的核心在于节点结构、入口指针和前驱节点处理
- 头结点、循环链表、双向链表都是链式结构的重要变形
- 链表的访问方式更偏向顺序访问，而不是随机访问

后面再回头对比上一章会更清楚：数组描述强调随机访问和连续空间，链式描述强调局部修改和结构灵活性。二者都是线性表的实现，只是适用场景和代价不同。
