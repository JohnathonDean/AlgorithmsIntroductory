# 矩阵


## 概述

矩阵可以看作数组描述在线性表之外的进一步扩展。在线性表中，元素按一个下标组织；在矩阵中，元素按行和列两个维度组织。

从参考书的思路看，矩阵这一部分真正重要的，不只是会写二维数组，而是理解：

- 二维结构怎样映射到一维存储空间
- 稠密矩阵与稀疏矩阵为什么需要不同表示方法
- 当零元素很多时，普通二维数组会造成大量空间浪费

因此，矩阵这一章既是数组表示思想的延伸，也是后面学习图、动态规划和数值结构时的重要基础。


## 矩阵的数据结构

### 1. 矩阵的概念定义

矩阵可以理解为由若干行、若干列元素组成的二维数据表。

如果用更数据结构化的方式理解，一个矩阵中的每个元素都由一对下标确定：

- 行下标
- 列下标

因此，矩阵中的位置不再只用一个 `index` 表示，而是用 `(i, j)` 表示。

这说明矩阵和线性表的主要区别在于：

- 线性表是单序列结构
- 矩阵是二维有序结构

### 2. 矩阵包含的基本操作

矩阵的基本操作通常包括：

- 建立一个矩阵
- 访问某个位置的元素
- 修改某个位置的元素
- 输出整个矩阵
- 执行转置、加法、乘法等矩阵运算

如果矩阵用于算法题或程序实现，还经常涉及：

- 按行遍历
- 按列遍历
- 按对角线或环形顺序遍历
- 判断某个坐标是否合法

### 3. 稠密矩阵与稀疏矩阵

在矩阵表示中，一个很重要的区分是：

- 稠密矩阵：大多数位置都有实际数据
- 稀疏矩阵：大多数位置都是零

当矩阵比较稠密时，直接使用二维数组最自然；

但当矩阵非常稀疏时，如果仍然保存所有零元素，就会产生明显的空间浪费。因此，稀疏矩阵通常要采用压缩存储。

### 4. 矩阵抽象上的关键认识

矩阵这一章最值得建立的意识是：

- 数学上的二维结构，程序里仍然要落实到某种具体存储表示

所以矩阵学习的重点并不只是“会用下标”，而是理解：

- 二维逻辑结构与一维物理存储之间的映射关系
- 不同矩阵特征会影响存储策略的选择

## 矩阵的描述

## 1. 二维数组描述

矩阵最直接的表示方法，就是使用二维数组。

这种表示的核心特点是：

- 元素按规则连续存放
- 可以用 `a[i][j]` 形式访问
- 适合稠密矩阵

如果矩阵规模不大，而且大多数位置都需要保存有效值，那么二维数组描述通常最直接、最清晰。

在这种表示里，最重要的不是语法本身，而是理解：

- `(i, j)` 这个二维位置，最终一定会映射到一段线性存储空间中

### 2. 行优先与列优先

二维数组虽然逻辑上是行列结构，但底层内存仍然是一维连续空间。

因此，矩阵元素的地址通常要通过地址公式计算出来。常见的两种组织方式是：

- 行优先
- 列优先

行优先意味着同一行元素在内存中连续；
列优先意味着同一列元素在内存中连续。

这部分内容和上一章数组描述的思想完全一致，只是从一维地址映射推广到了二维地址映射。

### 3. 稀疏矩阵的压缩表示

当矩阵中绝大多数元素都是零时，直接存整个二维数组往往不划算。

这时更合理的做法是：

- 只存非零元素
- 同时记录这些元素所在的位置

最常见的基本想法是用三元组表示一个非零项：

- 行号
- 列号
- 元素值

这样一来，矩阵的存储量就会和非零元素个数相关，而不再与总行列规模直接绑定。

这也是稀疏矩阵表示最重要的价值：

- 用更复杂一点的组织方式，换取大量空间节省

### 4. 特殊矩阵的存储思想

除了普通矩阵和稀疏矩阵，很多教材还会继续讨论一些特殊矩阵，例如：

- 对角矩阵
- 三角矩阵
- 对称矩阵
- 三对角矩阵

这些矩阵的共同特征是：

- 有很多位置天然不需要存储

因此，它们也常常使用压缩存储。学习这一部分的关键不是记住每一种具体公式，而是先理解一个统一思想：

- 当矩阵中存在大量“可预测的无效位置”时，就可以通过压缩表示减少空间浪费


## 总结

这一章的核心任务，是理解二维结构怎样在程序中组织和存储。

可以把主要认识归纳为：

- 矩阵是数组描述从一维向二维的自然推广
- 二维逻辑结构最终仍然要映射到线性存储空间
- 稠密矩阵通常适合直接使用二维数组
- 稀疏矩阵和特殊矩阵通常更适合压缩表示
- 矩阵这一章的本质，是学习“结构特点决定存储方式”

后面学习图、动态规划和网格搜索问题时，矩阵中的坐标、遍历和存储思想都会反复出现。
