# 堆与优先队列


## 概述

堆与优先队列讨论的是另一类非常典型的问题：

- 数据不是简单地按先后顺序处理
- 而是希望每次都能快速取出“当前最重要”的元素

参考书在这里要强调的，是优先级这一概念对数据结构设计的影响。

在线性表、栈和队列中，处理顺序分别由位置规则决定；而在优先队列中，处理顺序由优先级决定。堆则是实现优先队列最经典、最常用的结构之一。


## 优先队列的数据结构

### 1. 优先队列的概念定义

优先队列是一种支持以下操作的结构：

- 插入一个新元素
- 删除或取得当前优先级最高的元素

它和普通队列的最大区别在于：

- 普通队列按进入先后顺序处理
- 优先队列按优先级高低处理

因此，优先队列并不强调“谁先来”，而强调“谁更重要”。

### 2. 优先队列包含的基本操作

优先队列中最核心的操作通常包括：

- 插入元素
- 读取当前最大值或最小值
- 删除当前最大值或最小值

如果从大根堆角度理解，常见操作就是：

- `insert(theElement)`
- `getMax()`
- `deleteMax()`

如果从小根堆角度理解，则对应为当前最小元素的维护。

### 3. 为什么堆适合实现优先队列

如果只用普通数组或链表实现优先队列，会面临明显问题：

- 插入容易时，取最值可能很慢
- 取最值容易时，插入又可能很慢

堆结构的价值就在于：

- 它在插入和删除最值之间取得了较好的平衡

这也是堆在算法题和工程实现中都非常常见的原因。

### 4. 优先队列抽象上的关键认识

这一章最值得建立的意识是：

- 堆不是为了“完全排序”而设计的
- 它只需要保证堆顶元素最特殊

因此，堆的重点不是整体有序，而是：

- 当前最值能够被快速访问和维护

## 堆的描述

## 1. 堆的基本性质

堆通常建立在完全二叉树基础上。

常见的两类堆是：

- 大根堆：每个节点都不小于其孩子节点
- 小根堆：每个节点都不大于其孩子节点

无论哪一种，堆都只保证局部有序，而不保证整棵树像排序数组那样全局有序。

这也是学习堆时最容易误解的地方：

- 堆有序，但只是局部有序

### 2. 堆的顺序表示

由于堆是完全二叉树，所以它非常适合用数组表示。

这也是堆和一般二叉树的重要差别之一：

- 普通二叉树更常用链式表示
- 堆更常用顺序表示

在数组表示中，父子节点之间有很自然的下标关系，因此：

- 可以不显式存储指针
- 直接通过下标找到父节点或孩子节点

这使得堆的实现非常紧凑。

### 3. 插入与删除最值

堆的两个核心维护过程通常是：

- 插入新元素时向上调整
- 删除堆顶后向下调整

从思想上看，这两个过程都在做同一件事：

- 破坏了堆性质之后，再把局部有序性恢复回来

因此，学习堆时最关键的不是死记代码，而是理解：

- 为什么插入后要向上调整
- 为什么删除堆顶后要向下调整

### 4. `priority_queue` 的理解

在 C++ 标准库中，`priority_queue` 可以看作优先队列的直接接口。

它的行为和本章堆的思想是对应的：

- 默认情况下通常表现为大根堆
- 通过比较规则可以改成小根堆

因此，学习堆之后，再看 `priority_queue` 的很多行为就会变得很自然：

- 为什么 `top()` 返回当前最值
- 为什么 `push()` 和 `pop()` 会维持堆结构
- 为什么它不适合像普通数组那样任意位置访问


## 总结

这一章的核心任务，是理解“按优先级处理元素”会导向怎样一种结构设计。

可以把主要认识归纳为：

- 优先队列按优先级而不是按到达顺序处理元素
- 堆是实现优先队列的经典结构
- 堆通常建立在完全二叉树和数组表示基础上
- 堆只保证局部有序，不保证整体排序
- 堆的价值在于高效维护当前最大值或最小值

后面学习二叉搜索树时，可以继续和堆对照理解：二者都和二叉树有关，但一个强调维护当前最值，一个强调按大小关系查找。
